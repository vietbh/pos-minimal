# PHASE 2.27 — PaymentReference + QR + Expiration + Regeneration + Completion Policy

## Implementation status

Implemented against the current repository snapshot.

## Core flow

```text
Bank Transfer checkout
    ↓
Order created as DRAFT
    ↓
PaymentReference generated and persisted
    ↓
QR generated from persisted payment data
    ↓
5-minute configurable expiration
    ↓
Customer transfers money
    ↓
Bank webhook
    ↓
PAY reference normalized and resolved
    ↓
Payment created exactly once
    ↓
PaymentReference → MATCHED
    ↓
Completion Policy
    ├── MANUAL → Order remains DRAFT → cashier Complete sale
    └── AUTO   → existing Complete Sale application flow → Order COMPLETED
```

## Important behavior

- PaymentReference is generated by the backend during bank-transfer payment-instruction/QR creation.
- Default expiration is 5 minutes.
- Expiration remains backend-authoritative.
- Frontend countdown is presentation-only.
- Expired references remain persisted.
- Regeneration creates a new unique reference and never reuses the old one.
- Webhook never creates PaymentReference.
- Webhook creates the actual Payment only after successful reference reconciliation.
- Webhook reconciliation and Order completion are separate business operations.
- Bank Transfer supports two completion policies: `MANUAL` and `AUTO`.
- Default policy is `MANUAL`.
- `MANUAL`: successful bank reconciliation leaves Order `DRAFT`; POS displays Payment received and cashier explicitly presses Complete sale.
- `AUTO`: successful bank reconciliation invokes the same authoritative Complete Sale application flow and completes the Order automatically.
- AUTO does not directly assign `OrderStatus::COMPLETED` inside the webhook.
- Final stock mutation occurs only during the final Order completion flow.
- Duplicate webhook notifications remain idempotent.
- Concurrent webhook and completion operations are protected by existing database locking/transaction behavior.
- Provider is tracking metadata and is not used as the bank payment reference business matching key.

## Configuration

Use:

```dotenv
POS_BANK_TRANSFER_COMPLETION_POLICY=MANUAL
```

Allowed values:

```text
MANUAL
AUTO
```

## UI behavior

The POS displays a live current local time while the POS screen is active.

After bank-transfer checkout succeeds:

- backend PaymentReference is displayed;
- backend QR is displayed;
- expiration/countdown is displayed;
- POS waits for bank reconciliation;
- `MANUAL` policy: POS changes to Payment received and exposes Complete sale;
- `AUTO` policy: POS waits for the backend Order to become `COMPLETED`;
- the cart is only cleared after final Order completion.

## Database

`PaymentReference.payment_id` remains nullable while the reference is pending.

A Payment is attached only after successful bank reconciliation.
