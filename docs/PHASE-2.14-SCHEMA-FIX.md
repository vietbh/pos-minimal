# Phase 2.14 — Schema Fix

## Problem

The `OrderFinancialReversal` migration created two indexes with explicit names that differ from the names generated by the current Doctrine ORM mapping.

`doctrine:schema:update --dump-sql` reports:

```sql
ALTER TABLE order_financial_reversals RENAME INDEX uniq_order_financial_reversal_order TO UNIQ_C99FA1D8D9F6D38;
ALTER TABLE order_financial_reversals RENAME INDEX idx_order_financial_reversal_user TO IDX_C99FA1DA76ED395;
```

## Fix

Add `Version20260907120001` as a forward migration. It renames the two existing indexes to the names expected by Doctrine.

The previously executed `Version20260907120000` is intentionally not modified. This is important because changing an already-applied migration would make migration history dependent on which copy of the code is deployed.

## Apply

```bash
php bin/console doctrine:migrations:migrate --no-interaction
php bin/console doctrine:schema:validate
```

Expected result:

```text
[OK] The mapping files are correct.
[OK] The database schema is in sync with the current mapping file.
```

## Verification

```bash
php bin/console doctrine:schema:update --dump-sql
```

Expected: no SQL output.

Then run the release gate:

```bash
php bin/console lint:container
php bin/phpunit
php bin/console doctrine:schema:validate
php bin/console asset-map:compile
```

Do **not** use `doctrine:schema:update --force` to resolve this drift.
