# MacroDroid → Bank Notification Webhook

## 1. Endpoint

```text
POST /webhooks/bank-notification
```

Example:

```text
https://your-pos.example.com/webhooks/bank-notification
```

Authentication:

```http
X-Webhook-Token: <BANK_NOTIFICATION_WEBHOOK_TOKEN>
Content-Type: application/json
```

## 2. Generate the webhook secret

Generate a new secret:

```bash
php bin/console app:webhook:generate-token
```

Or generate and write/update `.env.local` automatically:

```bash
php bin/console app:webhook:generate-token --write-env-local
```

For production, prefer the server/container secret store instead of committing `.env.local`.

## 3. MacroDroid request body

MacroDroid should send the bank notification as normalized JSON:

```json
{
  "provider": "MACRODROID",
  "deviceId": "android-pos-01",
  "externalTransactionId": "MACRO-20260917-000001",
  "amount": 66000,
  "description": "PAY7K3M92X8 Chuyển khoản cho NGUYENVANA",
  "occurredAt": "2026-09-17T00:40:12+07:00",
  "bankAccountId": 1
}
```

Required fields:

- `externalTransactionId`: stable ID generated by MacroDroid for the notification/transaction; retries must reuse the same value.
- `amount`: received amount in VND.
- `description`: bank notification text, including the payment reference when available.
- `bankAccountId`: receiving account configured in POS.

`provider` defaults to `MACRODROID`.
`occurredAt` is optional; server time is used when omitted.
`deviceId` is optional but recommended for audit.

## 4. Payment reference

Payment Settings stores a template, not a fixed reference:

```text
{PAYMENT REFERENCE} Chuyển khoản cho BUIHOANGVIET
```

For one payment the POS generates, for example:

```text
7K3M92X8
```

The actual transfer content becomes:

```text
7K3M92X8 Chuyển khoản cho BUIHOANGVIET
```

MacroDroid should forward the notification text without rewriting the payment reference.

Symfony extracts the `PAY-...` reference and matches it to `Payment.reference`.

## 5. Reconciliation rules

The webhook is accepted only after the token is verified.

A transaction is `MATCHED` only when:

1. `externalTransactionId` has not already been processed.
2. The receiving bank account exists and is active.
3. The payment reference exists.
4. The payment belongs to the same receiving bank account.
5. The received amount equals the payment amount.

Otherwise the transaction is retained with an explicit non-matched status such as `DUPLICATE`, `CONFLICT`, `REFERENCE_NOT_FOUND`, or `UNMATCHED`.

## 6. Idempotency

The unique key is:

```text
provider + externalTransactionId
```

If MacroDroid retries the same bank notification, Symfony returns `DUPLICATE` and does not create another external transaction.

## 7. Test with curl

After configuring the token:

```bash
curl -i -X POST 'https://your-pos.example.com/webhooks/bank-notification' \
  -H 'Content-Type: application/json' \
  -H 'X-Webhook-Token: YOUR_TOKEN' \
  --data '{
    "provider":"MACRODROID",
    "deviceId":"android-pos-01",
    "externalTransactionId":"TEST-000001",
    "amount":66000,
    "description":"7K3M92X8 Chuyển khoản cho BUIHOANGVIET",
    "occurredAt":"2026-09-17T00:40:12+07:00",
    "bankAccountId":1
  }'
```

Do not use a real bank transaction for the first connectivity test.
